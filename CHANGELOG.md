# Changelog

Все заметные изменения этого проекта документируются здесь.

Формат основан на [Keep a Changelog 1.1.0](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

Разделы: `Added` (добавлено), `Changed` (изменено), `Deprecated` (устарело),
`Removed` (удалено), `Fixed` (исправлено), `Security` (безопасность).

## [0.2.0] (не выпущено)

Telegram-бот поверх готового ядра. Тег появится после проверки на живом
бот-аккаунте, до этого версия считается в разработке.

### Added

- Бот на aiogram 3: команды `/start`, `/help`, `/about` и свободный текст с
  ингредиентами через запятую. Ответ содержит до пяти коктейлей, у каждого
  строка «докупить: ...» и покрытие вида `3/4`.
- Кнопки под ответом пересчитывают подбор с порогом «сколько готов докупить»
  (0, 1, 2 или 3). Список ингредиентов не кладётся в `callback_data`
  (лимит Telegram в 64 байта), вместо него короткий ключ и `QueryCache`
  в памяти процесса.
- Автоматический подъём порога: если при `max_missing=0` ничего не нашлось,
  бот сам пробует 2 и честно сообщает «точных совпадений нет».
- Разделение слоёв: `bot/service.py` содержит логику ответа и не импортирует
  aiogram, `bot/handlers.py` только переводит её в сообщения, `bot/app.py`
  собирает диспетчер и запускает long polling.
- Команда `cocktail bot` с флагом `--token` и чтением `TELEGRAM_BOT_TOKEN`
  из окружения или `.env`. Без токена команда завершается с понятной
  подсказкой про @BotFather, а не трейсбеком.
- `Config.telegram_token` с валидацией пустых значений.
- Тесты: разбор ввода, callback-данные, кэш запросов, форматирование ответа,
  автофолбэк, ограничение длины сообщения, сборка диспетчера и разметки
  кнопок. Всё без сети и без токена.
- CI ставит extras `bot`, поэтому тесты бота выполняются на Ubuntu и Windows.

### Changed

- Внутри страницы появилось листание: восемь карточек на лист, стрелки
  `◀ назад` и `вперёд ▶`, в шапке позиция вида «Показаны 9-16 из 33».
  Раньше на странице «докупить 2» могло быть 46 коктейлей, а показывались
  только первые пять, и добраться до остальных было нельзя.
- Стрелки не появляются, если в ту сторону нет карточек: на первом листе
  нет «назад», на последнем нет «вперёд». Кнопка, которая ничего не делает,
  раздражает сильнее отсутствующей.
- Нумерация карточек сквозная по странице (9, 10, 11...), а не с единицы
  на каждом листе: так видно, сколько уже пролистано.
- Кнопки бота переделаны в три страницы: «только своё», «докупить 1»,
  «докупить 2». Раньше это были пороги 0-3, и они не работали как интерфейс:
  результаты сортируются по числу недостающих, поэтому расширение порога
  добавляло варианты в конец списка, а первые пять оставались теми же.
  Кнопка меняла заголовок, но не содержимое. Теперь страница - это ровно
  N недостающих, и каждое нажатие даёт другой список.
- Пустые страницы не показываются кнопками: кнопка, ведущая на пустой экран,
  после автоперехода ещё и возвращала пользователя туда же, откуда он пришёл.
- В шапке сообщения видно режим и размер страницы: «Готово к приготовлению: 1»,
  «Докупить 1 ингредиент: 11».
- Версия 0.2.0. Дорожная карта: этап 6 (бот) закрыт, REST остаётся
  отложенным до появления потребителя вне процесса.

### Fixed

- Один и тот же `Router` подключался к диспетчеру при каждом создании бота,
  а aiogram запрещает подключать роутер дважды: второй `create_dispatcher`
  падал с `Router is already attached`. Теперь роутер собирается функцией
  `build_router()` на каждый диспетчер.
- Тесты больше не читают локальный `.env`: у разработчика с настоящим
  `TELEGRAM_BOT_TOKEN` тест «бот без токена» пытался подключиться к Telegram.

- CLI больше не падает с `UnicodeEncodeError`, если консоль не умеет
  печатать кириллицу. На Windows-раннере GitHub Actions кодировка cp1252,
  и любой русский текст в выводе (`find`, `report`, сообщения об ошибках)
  завершал команду трейсбеком. Теперь потоки переключаются в режим замены
  символов, вывод деградирует до `?`, а код возврата остаётся осмысленным.
- Ошибка кодировки больше не маскируется под «ошибку пользователя»:
  `UnicodeEncodeError` наследуется от `ValueError` и раньше попадал в общий
  обработчик, который падал повторно при печати сообщения.
- CI-шаг `Smoke test CLI` стал строгим: раньше он вызывал `cocktail find`
  через `|| echo "шаг пропущен"`, из-за чего реальный провал подбора
  выглядел как пропуск. Теперь шаг проверяет только то, что точки входа
  живы, а содержимое ответа на настоящем каталоге проверяет
  `tests/test_integration.py`: для полного набора ингредиентов первым
  возвращается `Gimlet` с покрытием 100%, а число коктейлей остаётся 441.

## [0.1.0] - 2026-11-01

Первый рабочий каркас: каталог скачивается, разбирается и ищется по
ингредиентам. Бота, REST и MCP пока нет - они следующие этапы.

### Added

- Каркас проекта: `pyproject.toml` (hatchling, версия из `cocktail.__version__`),
  строгие настройки ruff и mypy, pytest с `--strict-config`, CI на GitHub Actions
  (Ubuntu и Windows), `Makefile`.
- Модели предметной области: `Cocktail`, `IngredientMeasure` - неизменяемые,
  с сериализацией в JSON для снапшота.
- Загрузка каталога TheCocktailDB: клиент на `httpx`, обход по алфавиту
  (`a-z`, `0-9`), дедупликация по `idDrink`, атомарная запись снапшота
  через `.tmp` + rename.
- Разбор рецептов `parse.parse_measure`: числа, дроби (`1 1/2`, `½`, `1,5`),
  единицы (oz, cl, ml, dash, tsp, tbsp, …), «juice of 1/2», пометки
  «to taste»/«for garnish», сохранение исходной строки в `raw`.
- Нормализация названий: словарь алиасов из `data/aliases.yaml`
  (русские и английские синонимы) плюс токенизация со стоп-словами.
- Поиск `search.find`: сопоставление по канонам, множествам слов и вложенности
  с защитой от коротких слов; ранжирование по числу недостающих ингредиентов,
  затем по покрытию, затем по алфавиту - результат детерминирован.
- CLI на argparse: `fetch`, `find`, `report`, `version`, флаги `--json`,
  `--max-missing`, `--limit`, `--snapshot`, `-v`; коды возврата 0/1/130.
- Отчёт `report.build_report`: доля строк с количеством и единицей, частотные
  словари ингредиентов и нераспознанных строк - измеримая база для этапа 2.
- Словарь алиасов `data/aliases.yaml` с черновым набором (~90 канонических
  названий, включая русские формы); на реальном каталоге распознаётся 86,7%
  строк с количеством (441 напиток, 1730 строк ингредиентов).
- Тесты (pytest, без сети): разбор рецептов, нормализация, поиск, снапшот,
  клиент API на `httpx.MockTransport`, CLI, конфигурация, отчёт.
- Документация: README с быстрым стартом, структурой, правилами данных
  и дорожной картой; этот CHANGELOG.

### Notes

- Формат снапшота: `schema: 1`, сырые объекты API в `items` - разбор
  выполняется при загрузке, поэтому парсер можно менять без повторных
  скачиваний.
- Заглушка `cocktail.bot` фиксирует место для Telegram-бота; зависимость
  `aiogram` объявлена отдельным extras `[bot]` и на этом этапе не ставится.
