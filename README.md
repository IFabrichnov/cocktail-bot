# cocktail-bot

Подбор коктейлей по ингредиентам, которые уже есть под рукой.

Ядро детерминированное: пользователь вводит «джин, лайм, тоник» - получает
список коктейлей с оценкой «чего не хватает». Никаких LLM в ядре нет и не
нужно: подбор - это пересечение множеств, а не генерация текста.

Telegram-бот работает поверх того же ядра: присылаешь список ингредиентов
в чат - получаешь коктейли и кнопки «сколько готов докупить». Ядро при этом
не знает о Telegram, а бот не знает о базе данных.

**Текущая версия: 0.2.0** - каркас, загрузка каталога, разбор ингредиентов,
поиск в памяти, Telegram-бот. История изменений - в [CHANGELOG.md](CHANGELOG.md).

## Быстрый старт

Требуется Python 3.12+ (проверено на 3.13). Всё остальное ставится в
локальное окружение.

### Windows (PowerShell)

```powershell
cd D:\Projects\cocktail-bot

python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"

# скачать каталог один раз (36 запросов, ~440 напитков)
.venv\Scripts\python.exe -m cocktail fetch

# что можно сделать прямо сейчас
.venv\Scripts\python.exe -m cocktail find --have "джин, лайм, тоник"
```

### Linux / macOS

```bash
python -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"

.venv/bin/python -m cocktail fetch
.venv/bin/python -m cocktail find --have "джин, лайм, тоник"
```

### Если есть uv

```bash
uv sync --extra dev
uv run cocktail fetch
uv run cocktail find --have "джин, лайм, тоник"
```

После установки в окружение доступна команда `cocktail` (на Windows -
`.venv\Scripts\cocktail.exe`), так что `python -m cocktail` можно заменить на неё.

## Команды

| Команда | Что делает | Этап |
|---|---|---|
| `cocktail version` | версия пакета | 0 |
| `cocktail fetch` | скачать снапшот каталога в `data/raw/cocktails.json` | 1 |
| `cocktail report` | отчёт: сколько ингредиентов разобрано, топ частот, что не распознано | 2 |
| `cocktail find --have "..."` | подобрать коктейли | 3 |
| `cocktail bot` | запустить Telegram-бота (long polling) | 6 |

Полезные опции:

```powershell
# сколько ингредиентов готов докупить (по умолчанию 0 - только из того, что есть)
cocktail find --have "джин, лайм" --max-missing 1

# больше результатов и машиночитаемый вывод
cocktail find --have "ром, лайм, мята" --limit 10 --json

# перекачать каталог (по умолчанию существующий снапшот не перезаписывается)
cocktail fetch --force

# только часть алфавита - для быстрой проверки
cocktail --snapshot data/raw/probe.json fetch --letters abc

# отчёт в JSON - удобно сравнивать «до/после» при доработке парсера
cocktail report --json
```

Коды возврата: `0` - успех, `1` - ошибка (нет снапшота, сеть, неверные
аргументы), `130` - прерывание с клавиатуры.

├── data/
│   ├── aliases.yaml     # синонимы для поиска (версионируется)

## Telegram-бот

Бот нужен для того, чтобы подбор работал с телефона, а не только из
терминала.

### Как запустить

1. Напиши [@BotFather](https://t.me/BotFather) команду `/newbot`, получи токен
   вида `123456789:AA...`.
2. Положи токен в `.env` в корне проекта (файл в `.gitignore`):

   ```
   TELEGRAM_BOT_TOKEN=123456789:AA...
   ```

3. Установи extras бота и запусти:

   ```powershell
   .venv\Scripts\python.exe -m pip install -e ".[bot]"
   .venv\Scripts\python.exe -m cocktail bot
   ```

Остановить: `Ctrl+C`. Токен можно передать и флагом `--token`, но так он
попадёт в историю команд, поэтому лучше `.env`.

### Что умеет

| Действие | Результат |
|---|---|
| `/start` | инструкция и примеры |
| `/help` | как работает подбор |
| `/about` | откуда данные и почему без LLM |
| любой текст | карточка коктейля: фото, название, состав, чего не хватает |
| кнопки под ответом | переключение между тремя страницами подбора |
| стрелки | листание по одной карточке: «Назад к 2», «Вперёд к 4» |

Страницы - это три состояния подбора:

| Страница | Что показывает |
|---|---|
| «только своё» | можно приготовить прямо сейчас, ничего не покупая |
| «докупить 1» | не хватает ровно одного ингредиента |
| «докупить 2» | не хватает ровно двух |

Бот открывает строгую страницу. Если там пусто, он сам переходит к следующей
и пишет об этом: «Готовых коктейлей нет. Показываю ближайшее». Пустые страницы
не показываются кнопками - нажимать на кнопку, ведущую в пустоту, незачем.

Страницы сделаны раздельными, а не «не хуже, чем»: при сортировке по числу
недостающих расширение порога добавляло варианты в конец списка, и кнопка
меняла заголовок, но не содержимое. Теперь каждая кнопка меняет сам список.

Внутри страницы карточки показываются по одной: страница с тридцатью тремя
вариантами - это тридцать три сообщения со стрелками. В шапке видно позицию
(«Коктейль 6 из 33»). Стрелка появляется только если в ту сторону есть
карточки: на первой нет «назад», на последней нет «вперёд».

### Русский текст

Карточка приходит отдельным сообщением с фотографией напитка. Подпись:
английское название, русское в скобках, полный состав на русском.

```
**Whiskey Sour (Виски-сауэр)** - 3/5
**Состав:** купажированный виски (Blended whiskey), лимон (Lemon), сахарная пудра (Powdered sugar), вишня (Cherry)
**Докупить:** сахарная пудра, вишня
```

Фотографии берутся из поля `strDrinkThumb` каталога: они есть у всех 441
напитка, JPEG примерно 43 КБ. Бот отправляет ссылку, картинку скачивает
сервер Telegram, поэтому боту не нужно ничего загружать самому. Если ссылки
нет, сообщение уходит обычным текстом - на всякий случай.

В составе рядом с русским названием стоит оригинал в скобках: по нему ищут
и сверяются с меню. Если перевода нет, скобки не рисуются, а «Докупить»
всегда короткий список по-русски.

Название, «Состав» и «Докупить» выделены жирным: сообщения уходят с
`parse_mode=HTML`. Поэтому все динамические строки экранируются - например,
название «AT&T» уходит как `AT&amp;T`, иначе Telegram отклонил бы сообщение
с ошибкой разбора разметки.

Переводы лежат в `data/translations.yaml` и не связаны с поиском:
`aliases.yaml` отвечает за то, что вводит пользователь, `translations.yaml` -
за то, как это показать. Ингредиенты переведены полностью (300 из 300
названий, 100% строк), названия коктейлей - 189 из 441.

Правило: нет перевода - нет скобок. Придумывать русское название для
«Zizi Coin-coin» ради единообразия хуже, чем оставить английское.
Сколько переведено, показывает `cocktail report`:

```
Перевод ингредиентов: 300 из 300 названий, 100.0% строк
Перевод коктейлей: 189 из 441 (42.9%)
```

Состав собирается из тех же ингредиентов, что и подбор, поэтому если
в каталоге ингредиент указан дважды (у Whiskey Sour лимон и как сок,
и как слайс), в карточке он показывается один раз.

### Как устроено

Логика ответа (что написать, какие кнопки показать) вынесена в
`bot/service.py` и не импортирует aiogram. Обработчики в `bot/handlers.py`
только переводят `Reply` в сообщение Telegram. Благодаря этому поведение
бота проверяется тестами без сети и без токена.

Роутер собирается функцией `build_router()`, а не создаётся один раз при
импорте: aiogram не даёт подключить один объект `Router` к двум диспетчерам,
а диспетчеры нужны и в тестах, и при повторной инициализации.

Кнопки не хранят список ингредиентов в `callback_data`: Telegram
ограничивает это поле 64 байтами, а кириллица занимает по два байта на
букву. Вместо этого бот кладёт короткий ключ, а сам запрос держит в памяти
процесса (`QueryCache`). Обратная сторона: после перезапуска бота старые
кнопки отвечают «запрос устарел», это ожидаемо.

## Данные

**Источник:** [TheCocktailDB](https://www.thecocktaildb.com/), публичный
тестовый ключ `1`, регистрация не нужна.

**Снапшот вместо онлайн-запросов.** Каталог скачивается один раз
(`cocktail fetch`), сохраняется как есть - сырые объекты API, без
преобразований - и коммитится в репозиторий. Причины:

1. **Воспроизводимость.** Через месяц не нужно гадать, почему изменились
   результаты: данные те же.
2. **Скорость и офлайн.** Поиск не ходит в сеть и не упирается в лимиты.
3. **Разбор отделён от загрузки.** Парсер можно переписать и перепроверить,
   не делая ни одного запроса.

Снапшот атомарный: сначала пишется `.tmp`, затем переименовывается. На
OneDrive это спасает от полузаписанного файла, который потом синхронизируется.

**Алиасы.** `data/aliases.yaml` переводит пользовательские названия
(«джин», «сок лайма», «Fresh Lime Juice») к каноническим названиям каталога.
Словарь версионируется вместе с кодом: расширяй его по отчёту
`cocktail report` и по промахам `cocktail find`.

Важно: `lime` и `lime juice` - **разные** ингредиенты (фрукт и сок).
Словарь это учитывает, и при добавлении записей стоит помнить.

**Переводы.** `data/translations.yaml` - подписи для вывода: `gin: джин`,
`Margarita: Маргарита`. Файл отдельный от алиасов, потому что задачи разные:
синонимов у ингредиента может быть несколько, а подпись для чата нужна одна.
Покрытие видно в `cocktail report` и в JSON-выводе (`translations`).

## Как это работает

```
API ──fetch──► data/raw/cocktails.json   (сырые данные, коммитятся)
                        │
                        │ store.load_snapshot
                        ▼
              parse.cocktail_from_raw    (количество, единица, ингредиент)
                        │
                        ▼
                 search.find             (алиасы + токены + ранжирование)
                        │
              ┌─────────┴─────────┐
              ▼                   ▼
         CLI / JSON          bot/service ──► Telegram
```

Правило, которое держит архитектуру: **ядро не знает о транспорте.**
CLI и бот - тонкие адаптеры сверху; каждый следующий слой добавляется,
не ломая предыдущий.

## Качество кода

```bash
ruff check .          # стиль и потенциальные ошибки
ruff format .         # автоформатирование
mypy                  # строгая проверка типов (strict)
pytest                # тесты
pytest --cov=cocktail # покрытие
```

То же через `make`: `make lint`, `make format`, `make typecheck`, `make test`,
`make check` (всё сразу). На Windows без `make` используй команды напрямую
или `pyproject.toml`-настройки в IDE.

Тесты не ходят в сеть: клиент API тестируется на `httpx.MockTransport`,
поиск и разбор - на синтетическом снапшоте из `tests/conftest.py`, а логика
бота - на `bot/service.py` без aiogram и без токена.

## Дорожная карта

| Этап | Что | Готово, когда |
|---|---|---|
| **0. Каркас** ✅ | репозиторий, uv/venv, ruff, mypy, pytest, CI | `make check` зелёный |
| **1. Данные** ✅ | клиент API, снапшот каталога | `cocktail fetch` → 441 напиток |
| **2. Разбор** 🚧 | ингредиенты, единицы, алиасы | `cocktail report` → ≥95% с количеством |
| **3. Поиск** ✅ | in-memory индекс, CLI, тесты | `cocktail find` выдаёт топ-5 |
| **6. Бот** ✅ | aiogram поверх ядра, кнопки порога | `/start` и текст в чате дают коктейли |
| 4. Хранилище | SQLite/Postgres | когда данные перестанут влезать в память |
| 5. REST | FastAPI | когда появится потребитель вне процесса |
| 7. MCP | тонкий адаптер | если появится LLM-клиент |

Почему MCP отложен: MCP нужен, чтобы **чужой LLM-клиент** (Claude Desktop,
Open WebUI, Hermes) узнал про твои инструменты. Пока потребитель - только
свой код и Telegram-бот, MCP был бы лишним слоем и лишним хопом. Решение
пересматривается, когда появится реальный потребитель-модель.

## Версионирование

Правила простые и обязательные:

1. Версия живёт **в одном месте** - `src/cocktail/__init__.py` (`__version__`).
   `pyproject.toml` читает её через hatchling; дублировать номер в двух файлах
   нельзя.
2. [CHANGELOG.md](CHANGELOG.md) ведётся по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
   версии - по [SemVer](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`.
   - `MAJOR` - ломающее изменение CLI, формата снапшота или API;
   - `MINOR` - новая функциональность без поломок;
   - `PATCH` - исправления и внутренние улучшения.
3. Каждое изменение поведения - запись в разделе `Unreleased`. Перед релизом
   `Unreleased` становится версией с датой, версия в `__init__.py` поднимается,
   ставится git-тег `vX.Y.Z`.
4. Версия схемы снапшота (`store.SNAPSHOT_SCHEMA`) меняется только при
   несовместимом изменении формата - это `MAJOR` для данных, и старая версия
   явно отклоняется с подсказкой пересоздать снапшот.

## Известные ограничения

- **Разбор не идеален.** 86,7% строк имеют распознанное количество (см.
  `cocktail report`). Остальное - в основном ингредиенты вообще без количества
  («Ice», «Salt»: в API поле пустое) и вольные формулировки вроде «Top soda
  water». Такие случаи видны в отчёте и закрываются по мере надобности.
- **Каталог на английском.** Русский ввод работает через `aliases.yaml`:
  чем больше записей, тем меньше промахов.
- **Поиск в памяти.** ~440 коктейлей - это доли мегабайта; БД появится
  только когда данные перестанут помещаться в память.
- **Тестовый ключ API** может быть ограничен по нагрузке. Поэтому снапшот
  и коммитится: повторные скачивания нужны редко.
- **Запуск под DSH-песочницей на Windows.** Если `pytest` падает с
  `PermissionError [WinError 5]` на временных каталогах - это ограничение
  песочницы, а не тестов: такие запуски нужны с полным доступом к файлам.
  В обычном терминале и в CI этого не происходит.
